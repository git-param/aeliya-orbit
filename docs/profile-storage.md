# Employee self profile

- Clicking the top bar profile opens `/profile`. A linked employee can edit their address and profile photo position, upload or remove their portrait, upload an Aadhaar card and PAN card, and add or remove secondary mobile numbers. Removing a portrait deletes both its file and any older database image, without deleting identity documents. The primary mobile remains part of the admin/HR employee editor. Self profile endpoints never accept a primary mobile update.
- New uploads are stored in `user-data/<user-id>/profile`, `user-data/<user-id>/aadhar`, and `user-data/<user-id>/pan` without extensions. The default `user-data` directory is a sibling of `backend` when launched from `backend`, or directly under the repository when launched from its root. Set `USER_DATA_DIR` to an absolute dedicated directory in deployment. The directory is excluded from Git and needs a deployment backup plan.
- Uploads stream to a temporary file, validate image/PDF signatures, and replace the target atomically where the filesystem supports it. The application has no multipart size cap; available disk space and any upstream proxy limits still apply. On POSIX filesystems, user directories and files are owner-only. Old profile pictures in PostgreSQL remain readable until replaced; new uploads use the filesystem.
- Aadhaar and PAN downloads resolve the authenticated employee's own user ID. Birthday portraits are available to authenticated users only while that employee appears in the current month's upcoming birthday carousel. Today's birthdays are included, past birthdays and next month's birthdays are excluded. The carousel shows the full image; the user-selected focus controls cropped avatar views.
